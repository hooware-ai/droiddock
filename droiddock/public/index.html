Help

These notes describe the current DroidDock controls. Opening Help does not send input to the phone. Help stays available while disconnected.

Pointer

  • Tap, drag, long-press, and scroll on the live phone video.
  • Hold Left Ctrl while wheeling over the live phone screen for temporary pinch-zoom near the pointer. Or turn on Map zoom to use the wheel without holding a key. Wheel up zooms in; wheel down zooms out. The Android app must support pinch gestures.
  • Phone controls stay unavailable until a live frame appears.

Keyboard

  • Focus the phone screen to type. Backspace, Delete, Enter, arrows, Home, End, Page Up, and Page Down go to the phone. Keyboard Home moves to the start of a line in supported text fields; use the rail's Home button to open the Android launcher. Other apps may handle navigation keys differently.
  • Tab stays in the browser. It does not send a Tab key to the phone.
  • Browser shortcuts that use Ctrl, Alt, or Command stay in the browser, except Left Ctrl with the wheel over the live phone screen.
  • DroidDock does not add global shortcut interception.

Escape

  • Escape first closes PIN entry and returns focus to its button. With PIN entry closed, Escape closes Help and returns focus to Help.
  • When pairing guidance is open, Escape closes it without sending Android Back.
  • Escape then closes Details and returns focus to Details and text input.
  • Escape that exits fullscreen does not send Android Back.
  • With PIN entry, Help, and Details closed, and the phone screen focused, Escape sends Back.

Paste

  • Press Ctrl+V over the focused phone screen to paste text, one image, or one file. Use Paste file if the browser does not expose copied files.
  • Unicode, emoji, and multiline text are supported when the Android app accepts them, up to 64 KiB of UTF-8.
  • Images and files up to 16 MiB need the optional Android paste helper. The focused Android app must support rich-content paste; use its Attach control if nothing appears.

Fallback text

  • Open Details and text input for fallback text. It uses scrcpy text injection.
  • Supports ASCII and some accented letters, not every Unicode character.
  • Limited to 300 UTF-8 bytes per send. A live N / 300 bytes counter uses the same check as Send.
  • Over-limit text stays in the field so it can be shortened.

Wireless pairing

  • A connection error does not prove pairing was lost. Check the phone's Wireless debugging screen first.
  • If the phone offers Pair device with pairing code, select Pair this computer in the control rail. Enter its temporary code only in the masked browser field.
  • If endpoint discovery is unavailable, enter the address and pairing port shown on the phone. Pairing success alone does not prove video is visible.
Phone unlock

Make sure the phone’s PIN field is ready to accept digits first. Lock detection cannot identify the authentication method or the focused field. Protected screens may stay black. Digits go to the focused phone field; some phones submit automatically. Unsupported prompts need the physical phone.

Type directly. No clipboard or saved PIN. Closing this panel or leaving this window clears the field. Sending digits does not send Enter.

Automatic detection is off. Manual entry is available.

Pair this computer

If wireless debugging lost its authorization, unlock the physical phone. In Developer options, open Wireless debugging, then choose Pair device with pairing code. Keep that phone screen open. Menus may vary by phone.

DroidDock checks for a temporary pairing endpoint on this network. Pairing is not confirmed until the configured phone is verified, and controls stay off until video appears.

Open the phone's pairing screen, then refresh the endpoint.

Enter the temporary code yourself. It is cleared after submit or whenever this panel closes; it is not saved or copied. A new code may be needed if the phone's pairing screen expires.
