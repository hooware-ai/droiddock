# Changelog

Changes are recorded here when they affect users or contributors, newest first, with the pull request that made each one. Published versions are the tagged [GitHub releases](https://github.com/hooware-ai/droiddock/releases); an entry under **Unreleased** is not in any release yet.

## Unreleased

- Audio spike: `docs/AUDIO-SPIKE.md` compares ways to play phone audio through Windows and recommends browser Opus playback, backed by a synthetic-audio proof in `scripts/audio-spike.mjs` and parser tests. Production audio stays off. (#98)
- The optional Android paste helper builds with Gradle 9.8.0. The new wrapper JAR and distribution match Gradle's published SHA-256 checksums, and the previous wrapper JAR's hash stays accepted in history. (#89)
- The public check no longer fails every pull request while another branch changes a pinned file (the scrcpy server, its license, or the Gradle wrapper JAR), such as a pending Gradle wrapper update. Pinned files must still match exactly in the checked-in content and in `HEAD`'s history, and earlier reviewed pins can be listed so an upgrade needs no history rewrite. Privacy checks still cover every branch. (#94)
- The optional Android paste helper build verifies a pinned SHA-256 checksum for every artifact it downloads, including the Android Gradle Plugin, its build dependencies, and the host-specific `aapt2` tool. `Install-PasteHelper.ps1` and CI build with `--dependency-verification strict`, and Dependabot now proposes plugin updates for review. See [Helper build dependency checksums](docs/SETUP.md#helper-build-dependency-checksums). (#88)
- A running service serves the browser page it started with and reports a non-secret `buildId` in `/api/status`, derived from the compiled server code and the served browser files. The launcher, `scripts/phone.mjs`, and `Test-DroidDock.mjs --live` report **Restart needed** instead of reusing a service from a different build of the checkout, and never stop it themselves. Opening the phone view is refused; status and disconnect still work so the session can be settled first. See [Update an installation](docs/SETUP.md#update-an-installation). (#86)
- Windows setup's test gate runs `npm run test:install`, the offline suite without publication and release-packaging tests, and reports a timeout (`offline_tests_timeout`) separately from a failing test (`offline_tests_failed`) without command output. `npm test`, `npm run verify`, and CI still run the full suite. (#85)
- Holding Shift with an arrow, Home, End, Page Up, or Page Down on the focused phone screen extends a text selection where the focused app and keyboard support it. Shift is not forwarded with other keys, and Ctrl, Alt, and Command shortcuts stay in the browser. (#84)
- File paste reports host staging failures (creating, writing, or closing the temporary file) with fixed guidance instead of raw filesystem messages, which could include the temporary path and local account name. A failed temporary-file removal no longer hides the original error, such as the 16 MiB limit. (#81)
- The focused phone screen sends Delete, Home, End, Page Up, and Page Down as Android editing and navigation keys. Keyboard Home moves to the start of a line in supported text fields instead of opening the launcher; the rail's Home button still opens the launcher. Apps may handle these keys differently. (#82)
- Optional local stream statistics in Details: video payload bytes per second, frames drawn per second, and decoder queue depth. Sampling runs only while Details is open in a visible, focused, connected tab, and nothing is saved or sent. A still screen may draw few frames; the numbers are not a latency measurement. (#62)
- System, Light, and Dark appearance choices in Details. System is the default and follows the browser's color preference; only the choice is saved locally. Themes recolor DroidDock's controls and background, never the phone image or connection. (#61)
- `node scripts/Test-DroidDock.mjs --support-summary` prints a compact Markdown table for help requests: fixed check names, result categories, the diagnostic schema, and validated tool versions only, with no messages, paths, device identities, endpoints, or command output. Default JSON output and exit codes are unchanged. (#60)
- Guided in-browser wireless pairing recovery. After a failed connection, the current controller can open a Pair panel, check for the pairing endpoint once or enter the address the phone shows, and submit a masked six-digit code. At most one bounded attempt runs at a time, and Connect, disconnect, handoff, or closing the controller cancels it. ADB receives the code only through standard input, and results never echo the code, endpoint, identity, or command output. The connection resumes only after the configured permanent phone identity is verified and a video frame renders. The physical phone must show **Pair device with pairing code**. (#57, #58, #59)
- When the configured phone is unreachable, a conservative, sanitized recovery hint may suggest wireless pairing. A `candidate` hint means only that one pairing advertisement could be associated with the configured phone's connect advertisement; it does not verify identity or prove that pairing was lost. Missing or ambiguous evidence stays `unknown`. (#53)
- Hold Left Ctrl while turning the wheel over the live phone screen to use Map zoom without switching it on; releasing the key returns to ordinary scrolling. The Zoom button's tooltip names the shortcut in both states. (#55, #56)
- Opt-in Map zoom mode maps mouse-wheel movement to a bounded two-finger pinch on the live phone screen. Ordinary scrolling remains available when the mode is off; disconnect and controller handoff clear the mode. (#52)
- Optional Android helper for explicit direct image/file paste into focused apps that accept rich content. One item per gesture, 16 MiB limit, session-bound local transfer, with a Paste file picker when the browser does not expose copied files. Other apps still need their own attachment controls. (#50)
- Setup and agent instructions agree on authorized use of a temporary ADB pairing code supplied for one phone: no duplicate entry, non-echo input preferred, and never saved in persistent or public artifacts. A private task transcript may still retain a code supplied there. (#45)
- Setup troubleshooting examples for unauthorized USB, missing PowerShell 7 or ADB, and wireless reconnects in [docs/TROUBLESHOOTING.md](docs/TROUBLESHOOTING.md). (#40)
- Opt-in automatic phone-unlock PIN panel, based on bounded read-only lock-state probes. Manual PIN entry remains available from the rail; detection cannot identify the authentication method or guarantee that the phone field is ready. PIN, Help, and Details panels close safely without sending Android Back. (#32)
- In-app Help panel on the side rail documenting current keyboard, pointer, paste, and fallback-text behavior, including focus requirements, Escape/Back, and byte limits. Help is static, usable while disconnected, restores focus to its trigger, and does not send phone input. (#33)
- Manual, masked phone PIN entry using standard Android digit key events, with separate Backspace and Enter controls, no automatic submission or retry, and clearing on send, panel closure, focus loss and session loss. Protected-screen visibility and remote biometric authentication remain unsupported. (#30)
- Deterministic offline tests of the real session-startup cancellation path between discovery, vendor push, and tunnel allocation, including a replacement Connect during a cancelled start. Production code is unchanged. (#23)
- Connection progress reports the current startup stage (finding the phone, preparing the connection, opening the video stream) without percentages or time estimates. Messages stay sanitized, cancelled or replaced sessions cannot overwrite a newer status, and browser input stays gated until a frame renders. (#22)
- Optional fullscreen phone view: a keyboard-accessible Enter/Exit control on the rail when the Fullscreen API is available, dock-level fullscreen so the phone and essential controls stay together, UI state from `fullscreenchange`, denied or unsupported requests leave the ordinary view and session in place, and Escape that exits fullscreen does not send Android Back. (#21)
- Live UTF-8 byte counter on fallback text input (`N / 300 bytes`), with an explicit over-limit state, associated help, and no silent truncation. (#19)
- Keyboard and focus accessibility on the browser chrome: a rail focus outline with at least 3:1 contrast on its light backgrounds and a canvas outline tested against black, a connection status live region outside the details panel, Escape that closes that panel before sending Android Back, and offline tests of names, tab order, and keyboard behavior on a synthetic screen. (#12)
- Compatibility notes that record CI coverage, intended setup requirements, and the empty live Android/browser matrix, plus how to report a sanitized result. (#11)
- Dependency and workflow updates: TypeScript 7.0.2 (#1), `@types/node` 26.6.2 (#2, #46), CodeQL actions 4.38.2 (#3, #47, #96), and `actions/upload-artifact` 7.0.1 (#4).

## 0.1.0 - 2026-09-18

First public preview, published as the `v0.1.0` GitHub pre-release. Initial public source distribution of DroidDock by Hooware:

- Local browser video and structured Android controls through the pinned, unmodified scrcpy 4.1 server.
- H.264 decoding through WebCodecs, keyboard input, mouse/touch controls, and explicit plain-text clipboard paste.
- Single-controller browser handoff with stale-view protection and scoped session cleanup.
- Windows setup, phone discovery, launch, lifecycle, and diagnostic helpers.
- Optional local Codex browser-panel workflow.
- Offline tests for protocol handling, HTTP/WebSocket boundaries, ownership, setup, diagnostics, and lifecycle operations.
- Public setup, contributor, support, security, architecture, and roadmap documentation.
- Bounded subprocess execution, redacted command errors, and retryable cleanup that verifies the intended device.
- Publication checks for private data, credentials, source provenance, and release archive contents.
- Reproducible source archives with checksums, dependency updates, and pinned CI and security workflows.

No live-phone compatibility matrix or stable-release support promise is established by this initial source distribution.
